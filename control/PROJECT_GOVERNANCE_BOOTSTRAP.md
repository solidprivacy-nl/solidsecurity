## Local scope

SolidSecurity is an AI-first managed compliance project for small healthcare organizations and SMEs facing security, privacy, AI-governance, certification-readiness and NIS2/Cybersecurity Act supply-chain pressure.

The project deliberately starts with a small control and workflow backbone. Customer-environment scanning, automated technical evidence collection, production integrations and broad platform implementation are outside the initial concept stage unless separately authorized through governed work.

## Authority boundaries

- GitHub is source of truth for project state, decisions and governed work.
- Consequential implementation and assurance remain separated under the canonical Control standard.
- AI-generated analysis or documentation is never by itself a professional assurance conclusion.
- Real client data is not authorized during concept/bootstrap work.
- Autonomous final legal, certification or compliance decisions are not authorized.
- Product implementation is not authorized by this bootstrap alone; issue #1 governs the current concept work.

## Required project-local reads

Before consequential work, read at minimum:

1. canonical Control mandatory sources;
2. this bootstrap;
3. `control/CURRENT_STATE.md`;
4. `control/SOLIDSECURITY_ASSURANCE_CONTRACT_V1.md`;
5. the active GitHub issue/work contract;
6. relevant decisions, architecture, roadmap, tests and evidence once those records exist.
